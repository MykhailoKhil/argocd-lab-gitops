# T20: rollback = git revert

```bash
git log --oneline -5 -- apps/demo-api/overlays/dev/   # find the bad commit (e.g. Image Updater's tag bump)
git revert <sha> && git push
```

Why not the Rollback button / `argocd app rollback`?

- It deploys an old revision **without changing git**: git and the cluster disagree.
- Argo CD refuses it while auto-sync is on: `rollback cannot be initiated when auto-sync is enabled`.
- Here every app is generated by the ApplicationSet; switching auto-sync off in the UI is undone
  within seconds. So a UI rollback is effectively impossible, on purpose.
- `kubectl argo rollouts undo` is a cluster-side change too: self-heal brings the new tag back.

A revert travels the normal path: canary, analysis, k6. The rollback itself gets verified.

UI rollback is for emergencies only (git down, prod burning, no time for a PR) and must be
followed by a revert in git. Try both on dev and screenshot the auto-sync error for the README.
